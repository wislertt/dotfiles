# mise installs tools; Homebrew installs only macOS GUI apps, from a Brewfile

Every command-line tool comes from mise, so Setup is the same on any platform. GUI apps (Orca, Zed, Docker) are macOS casks that mise cannot install, so they live in a `Brewfile` (`src/lib/Brewfile`, not linked), applied only on macOS, and never with `brew bundle --cleanup` because that would remove apps installed by hand. A tool lives in exactly one of the two. We considered mise-only with a manual "install by hand" list (rejected: apps would be unreproducible) and Brewfile for everything (rejected: it ties the whole setup to Homebrew).

Casks float, so `Brewfile.lock.json` is not written, and mise tools float at `latest` too (pin one in `mise.toml` only when a release breaks it; no `mise.lock`, the rare drift is caught by the weekly Fresh-machine job). `bake update` upgrades them. Setup installs mise tools without upgrading them; Update upgrades. Homebrew holds nothing but what the Brewfiles declare, so Setup and Update run only `brew bundle`, never bakelib's blanket `brew upgrade`. The one formula allowed in a Brewfile is `brew "mise"`: mise is the bootstrap, installed by hand before Setup can run, and listing it lets Update upgrade it.

Setup and Update never remove anything. Moving a tool to mise leaves the old copy where it was: `bake duplicates` lists copies of declared mise tools elsewhere on `PATH`, matching by the binary names the mise copy ships, and removes nothing. We considered a command that uninstalled through each package manager (rejected: one adapter and parser per manager is a maintenance burden for a job done once per tool, and `PATH` shows which copy actually runs).

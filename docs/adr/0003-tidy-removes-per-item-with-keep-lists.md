# Tidy removes Strays without asking, with Keep lists

`bake tidy` finds Strays (anything installed that no mise config, Brewfile or Keep list accounts for) and removes each one it can with the manager that owns it, without asking. It runs `brew uninstall` (then `brew autoremove`) for a formula or cask in Homebrew's own `brew bundle cleanup` listing (without `--force`) for every Brewfile, with formulas limited to `brew leaves`. It also runs `uv tool uninstall`, `cargo uninstall`, `npm uninstall -g`, `pnpm remove -g`, `rustup toolchain uninstall` for a numbered or dated Rust toolchain that no repo pins (rustup installs a pinned one again on the next build; channels are never Strays, and only `rust-toolchain.toml` and `rust-toolchain` at repo roots one or two folders under the roots in `src/lib/tidy.toml` are read, so the scan stays cheap), `rm` for a dead link, make-writable-then-remove for a leftover tool-manager folder in the home directory, and `gh api -X DELETE` (with the stored gh login) for a GitHub signing key that has expired. Some Strays are only named with the command to run: anything needing sudo, GUI apps, unknown regular files in `~/.local/bin`, copies of a declared mise tool, signing keys that never expire and SSH keys on the GitHub account (git uses HTTPS, so every SSH key is a Stray, but one may still be in use). Bake never runs sudo, never deletes an app (it may be MDM-managed or hold data), never reads or deletes a file that may hold credentials, and never deletes a key that may have been added by hand. If a removal fails, Tidy reports it, carries on with the rest and exits nonzero. `bake tidy --check` lists every Stray, removes nothing and exits nonzero if there are any. It is not run in CI, where the runner's preinstalled software would fail it.

This reverses v1's report-only choice (v1 ticket 07, recorded in ADR 0002). That choice rejected per-manager uninstall code as a maintenance burden for a job done once per tool. Drift turned out not to be once per tool: finding it by hand took a day at the end of v1, and it comes back. Each manager needs only a listing and an uninstall command. The owner wants tidying to need no decisions, so the declarations and Keep lists are the whole truth: what they do not account for goes. `--check` is the preview, and the Keep list is where anything worth keeping is recorded. The v1 Duplicates report becomes one kind of Stray (a copy of a declared mise tool elsewhere on `PATH`), so `bake duplicates` is gone: two commands over overlapping ground would drift. Such a copy is still only named, because the path tells the owner which manager owns it and Tidy does not guess. The v1 `clean-signing-keys` command goes the same way, since an expired key is a Stray too.

Keep lists are TOML files of `"kind:name" = "one-line reason"`, keyed as Tidy prints a Stray. `src/lib/keep.toml` is in the public repo. `private/src/lib/keep.toml` is read only when the private companion is checked out and holds entries that reveal an account, employer or work setup. An entry without a kind or a reason fails the run.

`bake tidy --caches` adds a second, opt-in pass over Disposable state, so one command does the full cleanup without a third cleanup verb beside `clean` and `tidy`. It runs `docker system prune --all --force` (when Docker is running) and, on macOS, `mo clean`. Without a terminal Mole skips the system caches that need sudo, so bake still never runs sudo. Unused Docker volumes go only with `--volumes`, because a volume can hold a local database. The pass touches no Stray and reads no Keep list, and `--check` ignores it: caches always exist, so it would never pass.

Apply and Setup never remove; Update removes only old versions and caches it replaced (`mise prune`, `uv cache prune` and, on macOS, `brew cleanup`, after its upgrades). Every other removal happens only in Tidy, on demand. (Update's existing offer to delete other machines' expired signing keys from GitHub stays.)

Alternatives rejected:

- `brew leaves` and `brew list --cask` minus the Brewfile names: a formula a declared cask depends on is a leaf, so it would be removed. Homebrew's cleanup listing keeps it, and follows formula aliases and old names.
- Asking y/N for each Stray: every run would need decisions, and answers given on one run would not carry to the next. The Keep list records the decision once.
- Keep entries in the mise configs: they declare what to install, not what to leave alone.
